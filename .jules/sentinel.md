## 2025-05-15 - IDOR vulnerabilities in group and user parameters
**Vulnerability:** Multiple endpoints (details.php, override.php, clearsubmissions.php, export.php, release.php, and unlock_graders.php) were susceptible to Insecure Direct Object Reference (IDOR). They accepted parameters like `groupid` or `userid` and performed actions without verifying that these IDs belonged to the course context of the current activity.
**Learning:** In Moodle, `require_login()` and `require_capability()` validate that the *current user* has access to the *current context*, but they do not automatically ensure that other identifiers provided in the request (like a target group or user) are logically restricted to that same context.
**Prevention:** Always explicitly validate that all user-provided identifiers belong to the expected context. For groups, include the `courseid` in the database query (e.g., `$DB->get_record('groups', ['id' => $groupid, 'courseid' => $course->id], '*', MUST_EXIST)`). For users, verify enrollment or group membership within the specific context.
