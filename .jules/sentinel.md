## 2026-06-06 - [HIGH] IDOR and XSS Hardening
**Vulnerability:** Several entry points (`details.php`, `override.php`, `clearsubmissions.php`, `export.php`, `release.php`, and `classes/external/unlock_graders.php`) were found to be vulnerable to Insecure Direct Object Reference (IDOR) because they accepted `groupid` or `userid` parameters without validating them against the current course context. Additionally, Cross-Site Scripting (XSS) risks were identified in `locallib.php` and `renderer.php` due to unescaped user-controlled output (filenames and criteria descriptions).
**Learning:** In Moodle plugins, `require_login($course, true, $cm)` and `require_capability('mod/peerwork:grade', $context)` ensure that the user has access to the *module*, but they do not automatically validate that other parameters (like `groupid`) belong to that specific course. Attackers can exploit this by providing IDs from different courses to access or modify unauthorized data. Also, even trusted inputs like criteria descriptions should be escaped upon output to defend against "stored XSS" if the creation/editing forms ever have bypasses.
**Prevention:** Always validate ID parameters against the current context (e.g., `$DB->record_exists('groups', ['id' => $groupid, 'courseid' => $course->id])`). For user IDs, use `is_enrolled($context, $userid)` or verify group membership via `groups_get_members($groupid)`. Always use Moodle's `s()` function or `format_text()` when outputting any string that could have been provided by a user.
