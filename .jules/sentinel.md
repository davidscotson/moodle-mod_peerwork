## 2025-05-14 - Systemic IDOR Vulnerabilities in Request Parameter Handling
**Vulnerability:** Multiple endpoints (details.php, export.php, clearsubmissions.php, override.php, release.php, and external functions) used request parameters like `groupid`, `userid`, and `peerworkid` to fetch or modify data without verifying that these objects belonged to the authenticated course context.
**Learning:** `require_login($course)` and `require_capability(...)` only ensure the user has access to the course and the necessary permissions; they do not automatically validate that other request parameters are consistent with that course context. In a multi-tenant or multi-course environment like Moodle, failing to validate the context of every object ID provided in the request allows for cross-course data leaks and unauthorized modifications.
**Prevention:** Always call `require_login` and capability checks *before* performing database lookups with user-provided IDs. For every object retrieved via a request parameter, explicitly verify its owner context (e.g., `$group->courseid != $course->id`) and throw an exception if there is a mismatch.
