## 2026-07-18 - Systemic IDOR Remediation across Teacher-Facing Endpoints and External APIs
**Vulnerability:** Systemic Insecure Direct Object References (IDOR) across multiple teacher-facing endpoints (details.php, override.php, clearsubmissions.php, export.php, release.php) and the external API (unlock_graders.php). Unauthenticated or unauthorized users could query database records or execute actions on groups/users belonging to different courses.
**Learning:** Database queries using user-provided IDs (like groupid, peerworkid, graderid) were executed prior to performing require_login() and capability checks, or without verifying that the IDs belong to the authenticated course context.
**Prevention:** Always place require_login() and require_capability() before any request parameter database lookups. Explicitly validate that any provided groupid, peerworkid, or userid belongs to the authenticated course/activity context using $DB->record_exists, explicit equality checks, or is_enrolled/groups_is_member.
